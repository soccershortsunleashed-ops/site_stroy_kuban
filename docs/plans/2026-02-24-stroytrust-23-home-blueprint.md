# StroyTrust-23 Home Blueprint (Maman Reference)

## 1. Цель

Собрать понятный и реалистичный blueprint главной страницы на базе референса `maman-corp.com`:
- перенять логику расположения блоков и ощущение «сценарного» скролла;
- сохранить текущий корпоративный стиль StroyTrust-23;
- внедрять эффекты поэтапно, без резкого усложнения и без просадки производительности.

## 2. Что берем из референса

1. Сценарную структуру главной страницы (последовательность экранов).
2. Двухфазный ритм для секций: вход секции -> раскрытие контента.
3. Вертикальную навигационную индикацию прогресса по экранам.
4. Мягкие параллакс-слои и маски-переходы вместо резких смен.
5. Управляемую анимацию с жесткими ограничениями на мобильных.

## 3. Подходы и выбор

### Подход A: Полное повторение scroll-jacking (как в референсе)
- Плюсы: максимальная «похожесть».
- Минусы: высокий риск для UX, доступности и поддержки.

### Подход B (рекомендуемый): Гибридный сценарный скролл
- Плюсы: близкое ощущение референса без агрессивного перехвата колеса мыши.
- Минусы: потребуются дополнительные состояния секций и калибровка анимаций.

### Подход C: Только косметические анимации без изменения ритма страницы
- Плюсы: минимальные риски.
- Минусы: не даст эффекта «сценарной» подачи, которую вы хотите.

Решение: **Подход B**.

## 4. Blueprint секций главной

Текущая база: `web/app/page.tsx` уже содержит нужные опорные блоки (`ReferenceIntro`, `KpiStrip`, `ProcessReferenceSection`, `ProjectsCarousel` и т.д.).  
Blueprint фиксирует их в сценарную последовательность:

1. **Экран 01: Intro / бренд**
- Блок: `ReferenceIntro`
- Поведение: мягкий фон-паттерн + плавный вход текста/логотипа.
- KPI-счетчик внизу: доведение до `123` при каждом входе на экран.

2. **Экран 02: Ценность и позиционирование**
- Блоки: `HomeHero` + `KpiStrip`
- Поведение: карточки проявляются каскадом, счетчики и метрики активируются при появлении.

3. **Экран 03: Процесс**
- Блок: `ProcessReferenceSection`
- Поведение: каждый пункт получает «стеклянный» правый акцент и пошаговый reveal при скролле.

4. **Экран 04: Ключевые направления**
- Блок: `KeyActivitiesBento`
- Поведение: stagger-анимация карточек + легкая глубина слоев.

5. **Экран 05: Аналитика**
- Блок: `ProjectStatsChart`
- Поведение: графики рисуются поэтапно, без перегруза и с ограничением по времени.

6. **Экран 06: Портфолио**
- Блок: `ProjectsCarousel`
- Поведение: непрерывная лента + аккуратный zoom в превью при открытии.

7. **Экран 07: Финальный CTA/переход**
- Блок: финальная зона перед футером (можно собрать из текущих `Card`/`Button` shadcn).
- Поведение: короткий финальный reveal и навигация в ключевые разделы.

## 5. Матрица анимаций

Для каждого экрана фиксируются 2 стадии:

1. `enter`: появление секции (opacity + y + blur по токенам).
2. `focus`: раскрытие контента (локальные микроанимации внутри секции).

Глобальные правила:
- Длительности: `0.45-0.8s`.
- Без резких easing-кривых.
- На мобильных: без длинных sticky-участков и без тяжелых параллаксов.
- При `prefers-reduced-motion`: только базовый fade без scroll-driven эффектов.

## 6. Техническая схема внедрения

1. Не ломать структуру роутинга; внедрять в текущие секции.
2. Использовать существующие примитивы анимации (`PageReveal`, `ParallaxLayer`, `CountUp`) и расширять их параметрами.
3. UI-обвязка только через `shadcn`-компоненты (`Card`, `Badge`, `Button`, `Dialog`, `Tabs` и т.д.).
4. Добавить единый конфиг сцен главной (массив экранов с id, trigger, animation-profile).
5. Добавить индикатор прогресса экранов в правой части viewport (desktop-only).

## 7. Ограничения и риски

1. Не копировать 1-в-1 тяжелый scroll lock из референса.
2. Не добавлять сторонние тяжелые анимационные библиотеки без необходимости.
3. Не ломать текущий контент и тексты на русском.
4. Следить за GPU-нагрузкой (`blur`, `backdrop-filter`, canvas-слои).

## 8. Этапы реализации

### Этап 1 (MVP, 1 итерация)
1. Зафиксировать последовательность сцен на главной.
2. Добавить единые enter/focus состояния для каждого крупного блока.
3. Стабилизировать счетчик KPI до `123`.

### Этап 2 (UX-усиление)
1. Добавить вертикальный индикатор сцен.
2. Подтянуть ритм переходов между секциями.
3. Доработать «стеклянные» инфо-акценты в блоке процесса.

### Этап 3 (финальная полировка)
1. Выравнивание таймингов и микровзаимодействий.
2. Мобильная адаптация и reduced-motion профиль.
3. Финальная проверка производительности и регрессий.

## 9. Критерии приемки

1. Главная ощущается сценарной и «живой», без дерганий.
2. Все эффекты читаемы и не мешают контенту.
3. На мобильных нет тяжелого поведения скролла.
4. Сборка и проверки проходят: `npm run lint`, `npm run build`.
5. Визуальная логика блоков согласована с референсом, но в стиле StroyTrust-23.
